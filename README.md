# acadPaletteSetXDATA

WPF-панель управления свойствами и XDATA для **AutoCAD 2021**, **этапы 1–5** из [ТЗ](TZ.md).

Команда `XDATAPALETTE` показывает или скрывает единственный `PaletteSet`. Внутри —
вертикальные вкладки **«Свойства»**, **«XDATA»**, **«Команды»** справа. Панель можно
закреплять слева и справа, оставлять плавающей, сворачивать кнопкой автоскрытия
и закрывать. После закрытия команда снова показывает ту же панель и выбранную вкладку.
WPF-содержимое следует `COLORTHEME`: `0` — тёмная тема, `1` — светлая, в том числе
при изменении темы уже открытой панели.

[Рендеры настоящей WPF-панели в обеих темах](docs/screenshots/README.md).

Следующая очередь — система параметров BobrovXDATA (схема JSON → NOD → XDATA, единый VST
во вкладке «Свойства») — описана в [TZXDATA](TZXDATA.md).

Во вкладке «Свойства» используется макет этапа 2:

- `Тип`, `Номер`, `Название`, `Заголовок` — параметры выбранного объекта.
- Сворачиваемая «ССЫЛКА НА ПРОЕКТ» с текстовым полем ссылки/обозначения проекта.
- «МАТЕРИАЛЫ» — список с курсивными заголовками категорий и колонками действий,
  марки, количества, включения в спецификацию и примечания.
- Материалы группируются по категории; параметры и флаг спецификации доступны для группового редактирования.
- При узкой панели таблица прокручивается горизонтально, содержимое — вертикально.
  Поля и материал сохраняются при переключении вкладок, тем и скрытии панели.

Этап 3 отслеживает выделение `PICKFIRST` через `Document.ImpliedSelectionChanged`
и читает снимки данных в `Application.Idle`. При пустом выделении редактор неактивен;
выбор примитива заполняет параметры и материалы из XDATA и связанных XRecord.
Для нескольких объектов поля объединяются; список сверху выбирает **дерево отдельного объекта**.
Снятие выделения очищает данные; переключение/закрытие DWG меняет подписки и содержимое.
Завершение команды (включая Undo/Redo) повторно читает текущее выделение.

Вкладка «XDATA» содержит **Visual Tree String**: объект → RegApp → типизированные
значения/вложенные списки, а также пути XRecord и разобранные XML-деревья.
Неизвестные поля/приложения остаются в дереве, ошибки формата показываются над ним.
Объект без XDATA отображает пустые параметры, без данных предыдущего объекта.
`PICKFIRST` должен быть равен `1`; временные наборы выбора внутри выполняющейся
команды не заменяют текущий набор в панели.

Этап 4 сравнивает все пять полей и материалы всего выделения. Совпавшие значения
показываются как есть, отличающиеся/отсутствующие — курсивным плейсхолдером **«Разное»**;
флаг спецификации становится неопределённым. Ввод подтверждается Enter или выходом
из поля и записывает только изменённое поле **во все выбранные объекты** через одну
транзакцию. `+ Добавить` / `×` добавляют/удаляют марку во всём наборе, `✎` открывает
ячейки для редактирования. Флаг применяется щелчком. Изменение дерева в списке объектов
не меняет цель записи. Ошибка записи откатывает группу и показывается в панели.

Материалы сопоставляются по точной марке; неизвестные поля/приложения и уникальные
значения прочих полей сохраняются. Поддерживаются документированные XDATA и XML XRecord
этапа 3; ТЗ не предоставляет реальных образцов сериализации ESMT/BobrovXDATA.
[Правила сравнения, записи, ограничения и проверка](docs/group-editing.md),
[форматы данных](docs/xdata-format.md). Именованная блокировка и транзакция обеспечивают
нативную запись. Этап 5 выделяет сервис `XDataWriter`: все объекты проверяются до
первой записи, изменения фиксируются одним Commit или откатываются целиком;
неизменённые данные пропускаются. XML XRecord обновляются по захваченным ObjectId.
Смена общего поля сохраняет разные значения остальных полей.
[Запись DWG и сценарий Undo/Redo](docs/xdata-writing.md) описывает нативное действие,
автотесты и проверку в установленном AutoCAD 2021.
Самостоятельный WPF-предпросмотр сохраняет локальный черновик этапа 2.

## Сборка

Для задачи #11 добавлен отдельный автоматический цикл **acadPaletteSetXDATA.dll →
acadPaletteSetXDATA.zip → GitHub Release** после каждого push в `main` и при ручном
запуске Actions. Версия формируется автоматически; ZIP содержит единственную
DLL для AutoCAD 2021 / .NET Framework 4.8 / x64 без DLL Autodesk.
`acadPaletteSetXDATA.dll` содержит весь плагин: регистрацию `XDATAPALETTE`,
логику XDATA и WPF-панель с темами. Исходники общие с комплектом из трёх DLL
для разработки и дополнительных версий AutoCAD.
[Запуск, проверки, ошибки и повторная публикация](docs/build-release.md).

Нужны .NET SDK 8 или новее; для запуска — Windows и соответствующая версия AutoCAD.
Проекты используют опубликованные Autodesk пакеты API только для компиляции.

| Выходная сборка | API | Целевой AutoCAD |
| --- | --- | --- |
| `net48` (по умолчанию) | AutoCAD.NET 24.0.0 | **AutoCAD 2021 (.NET Framework 4.8)** |
| `net48` (отдельная сборка) | AutoCAD.NET 24.3.0 | AutoCAD 2024 (.NET Framework 4.8) |
| `net8.0-windows` | AutoCAD.NET 25.0.1 | AutoCAD 2025 (.NET 8) |

Цель AutoCAD 2021 и пакет 24.0.0 подтверждены [документацией Autodesk](https://blog.autodesk.io/autocad-2012-interoperability-for-customization/).
Версии пакетов закреплены намеренно: AutoCAD.NET 25.0.2 уже предназначен для .NET 10.
Для обновлённых выпусков AutoCAD с .NET 10 требуется отдельная проверка совместимости;
этот этап сохраняет указанные в ТЗ цели .NET Framework 4.8 и .NET 8.

```sh
dotnet build src/AcadPaletteSetXData.AutoCAD -c Release
dotnet test tests/AcadPaletteSetXData.Core.Tests -c Release
# Дополнительная проверка прежней цели AutoCAD 2024, в отдельную выходную папку:
dotnet build src/AcadPaletteSetXData.AutoCAD -c Release -f net48 -p:AutoCadNet48ApiVersion=24.3.0 -p:OutputPath=../../artifacts/autocad2024
```

Выход: `src/AcadPaletteSetXData.AutoCAD/bin/Release/<целевая платформа>/`.
Из этой папки скопируйте **все три** `AcadPaletteSetXData.*.dll` вместе в отдельную
папку плагина. Для .NET 8 сохраните рядом также `.deps.json`. DLL AutoCAD поставляются
самим AutoCAD, копировать их из NuGet или заменять ими установленные DLL не нужно.

## Загрузка

1. Добавьте папку плагина в доверенные расположения AutoCAD (`TRUSTEDPATHS`).
2. Распакуйте `acadPaletteSetXDATA.zip` из GitHub Release и в AutoCAD 2021 выполните
   `NETLOAD` для **`acadPaletteSetXDATA.dll`**. Дополнительные DLL плагина не нужны.
   В командной строке появится:
   `acadPaletteSetXDATA загружено. Команда XDATAPALETTE — показать/скрыть панель XDATA.`
   При загрузке без открытого чертежа сообщение появится после открытия первой DWG.
   Панель при загрузке не открывается.
3. Введите `XDATAPALETTE`. Повторный вызов скрывает панель.
4. Для закрепления перетащите заголовок к краю окна или воспользуйтесь меню панели.
   Кнопка автоскрытия сворачивает панель, кнопка закрытия скрывает её.

Для отдельной сборки из исходников загрузите `AcadPaletteSetXData.AutoCAD.dll`
из папки с тремя DLL нужной платформы. Проверяйте этот вариант и DLL из Release
в разных сеансах AutoCAD: они регистрируют одну и ту же команду.

## Архитектура и проверка

- `Core`: снимки типизированных данных, ограниченный парсер XDATA/XML, дерево,
  ViewModel выбора/свойств, слияние и операции одного поля, патчер XDATA/XML,
  `XDataWriter` с предварительной проверкой всей группы, команды черновика и контроллеры подписок; не зависит от AutoCAD/WPF.
- `UI`: WPF `UserControl`, привязки MVVM, группировка через `CollectionViewSource`,
  шаблоны строк/контролов, вертикальные вкладки и словари тем.
- `AutoCAD`: регистрация команды и приложения, адаптер `PaletteSet`, события
  изменения `COLORTHEME`, выбора и документов; чтение через `LockDocument` и
  `StartOpenCloseTransaction` с `OpenMode.ForRead`; запись группы через именованную блокировку
  и `AutoCadXDataWriteTransaction`/`StartTransaction` с Commit, освобождение всех `ResultBuffer`.
  Панель создаётся при первом вызове команды; при завершении
  приложения освобождается и отписывается от событий.
- `tests`: проверки выбора/очистки/ошибок/отписки, XDATA/XML и пределов парсера,
  жизненного цикла и темы, полей черновика, уведомлений и
  добавления/редактирования/удаления нужной строки, сохранения состояния при смене вкладок.

Проверки интерфейса запускаются на Windows, без AutoCAD, для обеих платформ:

```sh
dotnet build experiments/AcadPaletteSetXData.WpfSmoke -c Release
dotnet run --project experiments/AcadPaletteSetXData.WpfSmoke -c Release -f net8.0-windows --no-build -- artifacts/screenshots/net8
./experiments/AcadPaletteSetXData.WpfSmoke/bin/Release/net48/AcadPaletteSetXData.WpfSmoke.exe artifacts/screenshots/net48
```

Для интерактивного просмотра WPF-панели передайте `--interactive` вместо пути к PNG.
Только инструмент предпросмотра заполняет демонстрационные материалы по исходному
скриншоту; плагин не подставляет их в чертёж. Smoke-проверка отображает настоящий
`UserControl`, вводит значения в поля, вызывает кнопки через WPF automation peers,
проверяет перегруппировку, флаг спецификации, раскрытие секций, положение вкладок,
обе темы, прокрутку узкой панели, отсутствие ошибок привязок и освобождение ViewModel.
Дополнительно проверяются неактивность без выбора, режим чтения, смена выбранного
объекта через настоящий ComboBox, обе темы дерева, XRecord и снятие выделения.
Дополнительно проверяются плейсхолдеры «Разное», Enter/выход из поля без лишней записи,
редактирование/переименование материалов, group add/delete и флаг спецификации.
Дополнительно проверяется запись общего типа через `XDataWriter` с сохранением
индивидуальных названий/номеров и материалов. PNG этапов 2–5 сохраняются для каждой платформы.
CI выполняет эти проверки и публикует артефакты `wpf-renders`, `plugin-binaries`
и результаты unit-тестов. Это проверка WPF-содержимого; нативная рамка `PaletteSet`,
закрепление и автоскрытие проверяются в AutoCAD по [сценарию](docs/autocad-verification.md).
Пример чертёжных данных: [examples/stage3-selection.lsp](examples/stage3-selection.lsp).
Для диагностики установите `XDATAPALETTE_TRACE=1` в окружении **до запуска AutoCAD**:
после чтения/записи в командной строке выводятся число объектов, операция и время. По умолчанию трассировка отключена.
