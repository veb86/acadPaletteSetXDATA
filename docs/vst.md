# VST вкладки «Свойства»: отображение (TZXDATA, этап 5)

Этап 5 из [TZXDATA](../TZXDATA.md): вкладка «Свойства» — один виртуализированный список-дерево
(VST) с панелью управления сверху. Строки строятся из кэша значений этапа 3
([xdata-v2.md](xdata-v2.md)) и результатов `CalculatedString` этапа 4
([calculated-string.md](calculated-string.md)) — XDATA при построении не читается. На этом этапе
VST **только показывал** значения; ввод, `+ Добавить`, `×`/`✎` и «+ Параметр» добавлены этапом 6 —
[vst-editing.md](vst-editing.md). Сторонние DLL не нужны:
VST — стандартные `ListView` + `GridView` WPF с `VirtualizingStackPanel` в режиме `Recycling`.

`PropertyEditorView` с жёстко заданными полями «Тип / Номер / Название / …» и списками типов и
категорий материалов удалён. `PropertyEditorViewModel` остаётся только как модель полей прежнего
формата для `XDataPatch` (запись v1, этап 4 палитры) — в интерфейсе он больше не показывается.

## Панель управления (раздел 8.4)

Высота 32 px; слева направо:

| Элемент | Этап 5 |
| --- | --- |
| `▾ Шаблон` | Подпись шаблона выделения из схемы (`Устройство`), «Разное» при разных шаблонах, «нет» без шаблона. Выбор шаблона — этап 7. |
| `+` (Параметр) | Резерв, недоступна; с этапа 6 — меню параметров схемы ([vst-editing.md](vst-editing.md#-параметр-раздел-84)). |
| `⟳` | Перечитывает выделение (`SelectionViewModel.RequestRefresh` → `SelectionController`) и пересчитывает `CalculatedString`; без источника выделения перестраивает дерево. |
| `⊞` / `⊟` | Развернуть / свернуть все группы, категории и таблицы. |
| `Фильтр…` | Поиск без учёта регистра по `Caption`, `Id` и значению (кроме «Разное»). Совпавшая строка показывается со всем поддеревом, предки совпадений — раскрытыми; остальные строки скрываются. |
| `⚙` (Схема) | Справа; с этапа 8 — меню «Редактор схемы…», «Импорт JSON…», «Экспорт JSON…» ([schema-editor.md](schema-editor.md)). |

Под панелью — строка сообщения: «Выберите объекты в чертеже», «Нет данных BobrovXDATA: назначьте
шаблон.» с кнопкой «Назначить шаблон» (резерв `VELEC_TEMPLATE_APPLY`, этап 7), отсутствие схемы в
чертеже. Без выделения VST неактивен и пуст (раздел 8.5).

## Колонки (раздел 8.2)

| № | Заголовок | Параметр / группа | Строка `Table` |
| --- | --- | --- | --- |
| 0 | — | — | `×` `✎` (работают с этапа 6) |
| 1 | ПАРАМЕТР | `▸/▾`, отступ 14 px на уровень, `Caption` с единицей (`Мощность, кВт`); группы и категории — курсивом | значение колонки-ключа `Key` (`CD35`) |
| 2 | ЗНАЧЕНИЕ | значение по типу и `Editor.Precision`; умолчание — серым; «Разное» — серым курсивом; у таблицы — «3 строки» | вторая колонка таблицы (`Mat_Count`) |
| 3 | `●` | `●` задано, `○` по умолчанию, `ƒ` вычисляемое, `!` ошибка | флажок `Boolean`-колонки (`Mat_InSpec`), третье состояние — «Разное» |
| 4 | ПРИМЕЧАНИЕ | `Description`, «по умолчанию», текст ошибки | колонка примечания (`Mat_Comment`); у узла таблицы — `+ Добавить` (работает с этапа 6) |

- Ширины перетаскиваются за границу заголовка; при узкой палитре VST прокручивается по горизонтали.
- Колонки 0, 3 и 4 скрываются флажками контекстного меню заголовка (`ShowActionsColumn`,
  `ShowStateColumn`, `ShowNoteColumn`).
- Подсказка строки — `Id`, тип, описание или полный текст значений строки таблицы.

## Дерево

Порядок строк — порядок шаблона; группы — поле `group` параметра, в порядке первого появления:

```text
▾ Общие                        Тип устройства · Класс · Наименование
▾ Обозначение                  Головное устройство · Группа · Обозначение (ƒ)
▾ Электрика                    Мощность, кВт · Ток, А · Напряжение · Фаза
▾ Материалы             3 строки   (группа из одной таблицы схлопывается в узел таблицы)
    ▾ Линейная арматура        GroupBy = Mat_Category, подпись элемента ENUM
        CD35        2   ☑   Пример
    ▾ Железобетонные элементы
        СВ110-5     1   ▣   (флаг различается в выделении)
▾ Дополнительные               параметры схемы вне шаблона объекта
▸ Не описаны в схеме (N)       Id без описания в NOD: «!», «× — удалить значение» (этап 6), свёрнута
▾ Прежний формат (только чтение)  ESMT_LEP_v1.0, SMARTLINE, BobrovXDATA v1 (BobrovXDATA_V1) и XML (VELEC_MIGRATE, этап 9)
```

Множественное выделение — объединение параметров всех объектов; различающиеся или отсутствующие
значения — «Разное». Строки таблиц объединяются по колонке-ключу: у общей строки различающиеся
колонки — «Разное»; строка, которой нет у части объектов, целиком показывается как «Разное»
(вместе с категорией), флажок — в третьем состоянии.

Управление деревом: `▸/▾`, двойной щелчок по строке, `→`/`+` — развернуть, `←`/`−` — свернуть,
`Enter`/`Пробел` — переключить. Раскрытие групп и вертикальная прокрутка запоминаются по набору
шаблонов выделения (`TemplateKey`): новое выделение того же шаблона открывается в том же виде
(раздел 8.5). Ширины колонок сохраняются на время сеанса AutoCAD.

## Производительность (раздел 10)

- `PropertyGridViewModel` строит дерево по `SelectionViewModel.Values` (кэш значений) и
  `Calculations` (формулы); видимые строки — плоский `ObservableCollection<PropertyRow>`.
  Раскрытие группы вставляет/удаляет только её строки, без перестроения.
- `ListView` с `VirtualizingPanel.IsVirtualizing=True` и `VirtualizationMode=Recycling`: контейнеры
  создаются только для видимых строк (smoke проверяет 400+ строк таблицы).
- Тесты `ThousandObjectsWithFiftyParametersAreBuiltWithinTheBudget` и `LoadTests` (этап 10): 1000 объектов ×
  50 параметров строятся не дольше 300 мс после чтения снимков. При повторном выборе XDATA не разбирается:
  значения и дерево XDATA берутся из кэша значений (`ParseCount`, `TreeParseCount`). Подробнее — в
  [performance.md](performance.md).
- `XDATAPALETTE_TRACE=1` выводит после каждого построения:
  `[XDATAPALETTE] VST: объектов 2, строк 24, видимых 21; 1.8 мс. Разборов XDATA: 2, деревьев XDATA: 2.`

## Проверка

```bash
DOTNET_ROLL_FORWARD=Major dotnet test tests/AcadPaletteSetXData.Core.Tests -c Release
dotnet build experiments/AcadPaletteSetXData.WpfSmoke -c Release
# Windows: рендеры в каталог
dotnet run --project experiments/AcadPaletteSetXData.WpfSmoke -c Release -f net48 -- artifacts/screenshots/net48
```

WPF smoke (CI, артефакт `wpf-renders`) на net48 и net8 в обеих темах проверяет: пустое
выделение, колонки и состояния `●/○/ƒ`, «Разное» серым курсивом, трёхпозиционный флажок,
`×`/`✎`/`+ Добавить`, `▸/▾` и клавиатуру, `⟳`/`⊞`/`⊟`, фильтр, меню колонок, виртуализацию,
сохранение раскрытия и прокрутки по шаблону, предложение «Назначить шаблон», прежний формат,
вкладку «XDATA», минимальный размер 280 × 320 с горизонтальной прокруткой, отсутствие ошибок
привязок. Рендеры — в [screenshots](screenshots/README.md).

## Ограничения этапа

- Только чтение: редактирование ячеек, `+ Параметр`, `+ Добавить`, `×`/`✎` — этап 6
  ([vst-editing.md](vst-editing.md));
  «Назначить шаблон» и выбор шаблона — этап 7; «⚙ Схема» — этап 8 ([schema-editor.md](schema-editor.md)).
- Ширины колонок и видимость колонок не записываются в файл настроек пользователя: в плагине
  ещё нет хранилища настроек, они живут до закрытия AutoCAD.
- Меню переполнения `»` для узкой панели не сделано: панель управления сжимает поле фильтра,
  а VST прокручивается по горизонтали.
