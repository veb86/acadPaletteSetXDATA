# Этап 5: запись DWG и Undo/Redo

Основная цель — **AutoCAD 2021**, `net48`, Autodesk API `24.0.0`. Этап 5 выделяет
сервис `XDataWriter` и закрепляет транзакционную запись этапа 4.

## Одна подтверждённая операция

`SelectionEdit` содержит только изменённое поле или действие с материалом.
Объединённая ViewModel с плейсхолдерами «Разное» целиком не сериализуется.
Например, если у двух объектов `Type=Cable`, но разные `Name`, `Number`, количество
и флаг CD35, изменение типа на `Device` сохраняет все эти индивидуальные значения.
Буквальный ввод `Разное` по-прежнему допустим; сам плейсхолдер в DWG не попадает.

Порядок записи:

1. Адаптер выделения проверяет активный документ, документ последнего чтения
   и отсутствие выполняющейся команды.
2. `AutoCadXDataWriteTransaction` получает именованную блокировку
   `LockDocument(Write, "XDATAPALETTEEDIT", "Изменение XDATA", false)`, сверяет
   весь PICKFIRST-набор с запрошенными идентификаторами и открывает **одну**
   `db.TransactionManager.StartTransaction()`.
3. В этой транзакции читает свежие XDATA и XRecord всех объектов в режиме `ForRead`.
   Чтение запоминает реальные `ObjectId` XRecord: отображаемый путь словаря
   не используется для поиска при записи.
4. `XDataWriter` применяет `XDataPatch` отдельно к каждому снимку. Проверяет
   форматы/предупреждения и лимит строк XDATA **до первой записи**. Неизменённые
   снимки пропускает. Операция без изменений не открывает объекты `ForWrite`
   и не вызывает `Commit`; XML с тем же значением сохраняет исходный буфер/форматирование.
5. Для изменённых объектов открывает сущность `ForWrite` (также при записи XML),
   регистрирует отсутствующий RegApp, создаёт `ResultBuffer` из типизированных
   `DataValue` и назначает `Entity.XData` и/или `Xrecord.Data`.
6. Вызывает **один** `tr.Commit()` после всех записей. Любое исключение до Commit
   освобождает транзакцию без фиксации и откатывает всю группу, включая RegApp.
   Затем освобождаются буферы и блокировка; панель перечитывает DWG, показывая ошибку.

Строки `1000` ограничены 255 байт UTF-8, **включая `ключ=`**. Например, `Name=`
оставляет 250 байт для значения. Это консервативная проверка плагина; ограничения
общего объёма XDATA и допустимости DXF-кодов окончательно проверяет AutoCAD.
XML остаётся в существующем XRecord, разбивается на строки до 240 байт UTF-8
без разрыва surrogate pair и поддерживает более длинные значения.
Произвольные форматы ESMT/BobrovXDATA не преобразуются в выдуманный контракт:
поддерживаемая сериализация описана в [xdata-format.md](xdata-format.md).

## Нативная отмена

Именованная блокировка охватывает все изменения группы и задаёт одно действие
AutoCAD. `localCommandName` задаёт подпись действия при отмене — это поведение
описано в [Document.LockDocument](https://help.autodesk.com/cloudhelp/2022/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_ApplicationServices_Document_LockDocument_DocumentLockMode_string_string__MarshalAsUnmanagedType_U1__bool.html).
Открытие объектов для записи включает нативный учёт изменений для отмены:
[Upgrade and Downgrade Open Objects](https://help.autodesk.com/cloudhelp/2022/ENU/OARX-DevGuide-Managed/files/GUID-CC5CC229-B122-4897-A8DA-5C5ADADB0F38.htm).
Отдельный стек Undo в плагине не нужен. Ctrl+Z/U/UNDO и REDO управляются AutoCAD.

После `CommandEnded`, `CommandCancelled` или `CommandFailed` адаптер откладывает
обновление до `Application.Idle`/`Editor.IsQuiescent`. Панель читает сохранённое
состояние через `StartOpenCloseTransaction` и `ForRead`; чтение не регистрирует
RegApp и не открывает объекты для записи.

## Проверка

`XDataWriterTests` проверяет сохранение разных полей при изменении общего поля
в XDATA/XML, неизвестные DXF/бинарные значения и XRecord, атрибуты/ветки XML,
предварительную проверку всей группы, откат при ошибках второй записи и Commit,
изменившийся набор, дубли целей, свежие данные, отсутствие лишних записей и
границы байтовых лимитов. Двойник транзакции моделирует фиксацию/откат,
**не нативный стек Undo AutoCAD**.

Windows WPF smoke для net48/net8 использует настоящий `XDataWriter` с транзакцией
в памяти. Ввод общего типа через Enter оставляет разные названия, номера,
материалы и плейсхолдеры. Рендеры `stage5-before.png` / `stage5-after.png`
публикуются вместе с прежними сценариями в `wpf-renders`.

Для живой проверки AutoCAD 2021:

1. В новой DWG загрузите `examples/stage3-selection.lsp` и
   `examples/stage5-undo.lsp` через APPLOAD. Выполните `XDATASTAGE3SAMPLE`.
2. Покажите палитру, снова выделите два примитива и выполните `XDATASTAGE5BEFORE`.
   Он запоминает полные `entget`/XRecord-буферы по handle, ничего не записывая.
3. При необходимости повторно выделите эти объекты после завершения команды.
   Измените **одно** поле палитры, Enter; выполните `XDATASTAGE5AFTER`.
4. Выполните **U один раз**, затем `XDATASTAGE5CHECKUNDO`: ожидается `PASS`
   и точное восстановление всех исходных буферов обоих объектов.
5. Выполните **REDO**, затем `XDATASTAGE5CHECKREDO`: ожидается `PASS`
   и восстановление всех изменённых буферов. Это также проверяет сохранение Redo
   после чтения панели и read-only команды проверки.
6. Повторите для основных полей, поля/флага материала, добавления и удаления.
   Проверьте актуальные mixed-плейсхолдеры в панели после Undo/Redo.
7. Сохраните DWG, закройте/откройте её и повторно выделите объекты: значения должны
   сохраниться. Проверьте отказ и откат группы при заблокированном слое/ошибке формата.

Скрипт ограничен 16 выбранными объектами, 256 записями на словарь и глубиной 32;
используйте небольшой пример. Детали остальных сценариев —
[autocad-verification.md](autocad-verification.md).
AutoCAD не установлен в Linux-среде разработки и Windows CI; нативный Undo/Redo
и повторное открытие DWG требуют выполнения этого сценария в установленном AutoCAD 2021.
