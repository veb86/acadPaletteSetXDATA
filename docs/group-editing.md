# Этап 4: «Разное» и групповое редактирование

«Свойства» всегда представляет **весь** PICKFIRST-набор. Список объектов сверху
выбирает только дерево на вкладке «XDATA», а не цель редактирования.

## Сравнение

Для пяти основных полей сравниваются значения всех объектов с учётом регистра и
пробелов. Отсутствующее поле отличается от присутствующего пустого поля. Совпавшее
значение показывается как есть; различающееся — пустым текстом с курсивным серым
плейсхолдером **Разное**. Плейсхолдер не входит в данные, а буквальный текст
`Разное` является допустимым значением.

ТЗ не задаёт ID материалов. Материалы объединяются по **точной марке (`Name`)**:
разные марки образуют отдельные строки. Категория, количество, флаг и примечание
сравниваются независимо. Если марка есть не у всех объектов или число её дублей
различается, все поля строки получают mixed-состояние. Разные категории показывают
заголовок группы «Разное». Nullable-флаг соответствует неопределённому состоянию;
`IsInSpecMixed` отличает расхождение от одинакового отсутствующего флага.

Повторения одной марки в одном объекте участвуют в сравнении; изменение/удаление
этой марки затрагивает все её повторения, в том числе в разных категориях и хранилищах.
Это соглашение можно заменить ID, когда появятся реальные образцы ESMT/BobrovXDATA.
Марка отсутствующей строки доступна в подсказке ячейки «МАРКА».

## Подтверждение и запись

- Измените поле, затем нажмите **Enter** или перейдите в другое поле. Только это
  поле записывается во все выбранные объекты; прочие значения и материалы остаются
  индивидуальными. Фокус без ввода и повторный Enter ничего не записывают.
- Backspace/Delete в пустом поле «Разное» явно очищает значение после подтверждения.
- Нажмите **✎**, чтобы редактировать ячейки материала; подтверждение аналогично.
  При изменении марки используется её исходное значение для поиска во всех объектах.
- Щелчок по флагу спецификации сразу применяет выбранное true/false/null к группе.
- **+ Добавить** сразу создаёт материал с уникальной начальной маркой
  `Новый материал N` во всех объектах и открывает строку для редактирования.
- **×** удаляет эту марку из всех объектов, где она есть.
- Изменение поля материала, отсутствующего на части объектов, создаёт там запись
  с исходной маркой и подтверждённым полем. Остальные поля остаются пустыми/nullable:
  разнородные значения не копируются из соседнего объекта.

`SelectionEdit` содержит одну операцию, а `XDataPatch` меняет документированный
формат этапа 3: известные ключи в ESMT/BobrovXDATA XDATA и `VisualTreeString` XML.
Существующие ключи и русские псевдонимы обновляются в своих местах, включая дубли.
Неизвестные RegApp, DXF-значения, поля, XML-атрибуты/ветки и посторонние XRecord
сохраняются. XML может изменить форматирование; семантика неизвестных узлов остаётся.
Если поля ещё нет, запись дополняет последний подходящий XML XRecord, иначе последний
известный RegApp, либо регистрирует `BobrovXDATA` для объекта без данных.

AutoCAD-адаптер проверяет активную DWG, отсутствие выполняющейся команды и точный
состав выделения. Затем открывает именованную блокировку документа `XDATAPALETTEEDIT`
и одну транзакцию, читает свежие значения и проверяет **все** изменения до записи.
Исключение на любом объекте откатывает группу; панель перечитывает сохранённые данные
и показывает ошибку. Некорректные/усечённые буферы с предупреждениями парсера запрещены
для записи. Строка XDATA ограничена 255 байт UTF-8; XML разбивается на чанки до 240
байт без разрыва Unicode-пар. Общий предел XDATA контролирует сам AutoCAD.

Именованная блокировка задаёт границу нативного действия для Undo; чтение после
Undo/Redo остаётся `StartOpenCloseTransaction`/ForRead. Подробности API:
[Document.LockDocument](https://help.autodesk.com/cloudhelp/2022/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_ApplicationServices_Document_LockDocument_DocumentLockMode_string_string__MarshalAsUnmanagedType_U1__bool.html).
Проверка реального Undo/Redo в AutoCAD 2021 обязательна по ручному сценарию:
Windows WPF CI и Linux unit-тесты не запускают AutoCAD.
Этап 5 выделяет отдельный `XDataWriter`, не записывает неизменённые снимки и
использует ObjectId XRecord при обновлении. Подробнее — [запись DWG](xdata-writing.md).

## Воспроизводимая проверка

`examples/stage3-selection.lsp` создаёт два объекта с общей маркой CD35 и разными
значениями в XDATA/XML. Выделите оба и выполните `XDATAPALETTE`: заголовки отличаются,
количество/флаг CD35 отличаются; смена объекта в списке меняет только дерево.
Измените название через Enter: оно станет одинаковым, количества останутся разными.
Добавьте/удалите материал и проверьте оба дерева, Undo/Redo и смену документа по
[docs/autocad-verification.md](autocad-verification.md).

Автоматически `GroupEditingTests` проверяет сравнение/отсутствие/дубли, границы
подтверждения, запись только изменённого поля, XDATA и XML, сохранение сторонних данных,
ошибки записи, group add/delete и буквальный текст «Разное». WPF smoke использует
тот же патчер с источником в памяти и проверяет настоящие контролы в двух темах и
двух runtime. Результаты — `stage4-*.png` в CI-артефакте `wpf-renders`.
